Fails the build when `github/codeql-action/init`, `autobuild`, `analyze` and `upload-sarif` are pinned to different releases anywhere in the repository.

## Why this exists

`init` writes a CodeQL config for the version it was built from; `autobuild` and `analyze` refuse to run against a config generated by a different release. These steps live in separate files — `src/security/codeql-init`, `src/security/codeql-analyze`, `.github/workflows/pr-security-scan.yml`, `.github/workflows/typescript-ci.yml`, `.github/workflows/go-security.yml` and `.github/workflows/go-pr-analysis.yml` — and Dependabot's `github-actions` ecosystem only scans `directory: "/"` ([`.github/dependabot.yml`](../../../.github/dependabot.yml)), so a bump to one file's pin does not propagate to the others. This check catches that drift at PR time instead of at CodeQL runtime.

## What it checks

Scans every `.yml`/`.yaml` file in the repo for `uses: github/codeql-action/<action>@<sha>` lines (`init`, `autobuild`, `analyze`, `upload-sarif`, or any other hyphenated sub-action), and fails if:

- any matching line is missing an exact `# vX.Y.Z` comment (a bare `# v4` is not enough to catch drift), or
- the pinned SHAs are not all identical — github/codeql-action publishes every sub-action from the same commit per release, so a differing SHA means a differing release even if the version comments happen to match.

## Inputs

| Input | Description | Required | Default |
|-------|-------------|----------|---------|
| _(none)_ | This action takes no inputs — it always scans the whole checked-out repository. | — | — |

## Usage

```yaml
- name: CodeQL Action Version Check
  uses: LerianStudio/github-actions-shared-workflows/src/lint/codeql-action-version-check@v1
```

## Required permissions

```yaml
permissions:
  contents: read
```
