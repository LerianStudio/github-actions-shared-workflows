Fails the build when `github/codeql-action/init`, `github/codeql-action/autobuild` and `github/codeql-action/analyze` are pinned to different releases anywhere in the repository.

## Why this exists

`init` writes a CodeQL config for the version it was built from; `autobuild` and `analyze` refuse to run against a config generated by a different release. The three steps live in separate files — `src/security/codeql-init`, `src/security/codeql-analyze` and `.github/workflows/pr-security-scan.yml` — and Dependabot's `github-actions` ecosystem only scans `directory: "/"` ([`.github/dependabot.yml`](../../../.github/dependabot.yml)), so a bump to one file's pin does not propagate to the others. This check catches that drift at PR time instead of at CodeQL runtime.

## What it checks

Scans every `.yml`/`.yaml` file in the repo for `uses: github/codeql-action/<action>@<sha>` lines, extracts the trailing `# vX.Y.Z` version comment, and fails if:

- any matching line is missing an exact `# vX.Y.Z` comment (a bare `# v4` is not enough to catch drift), or
- more than one distinct version is found across all matches.

## Usage

```yaml
- name: CodeQL Action Version Check
  uses: LerianStudio/github-actions-shared-workflows/src/lint/codeql-action-version-check@v1
```

No inputs — it always scans the whole checked-out repository.

## Required permissions

```yaml
permissions:
  contents: read
```
